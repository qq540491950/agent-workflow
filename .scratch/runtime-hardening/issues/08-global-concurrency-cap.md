# 08: 全局并发上限与 SYSTEM_BUSY

**What to build:** 运维人员可以设置全局最大活跃执行数。超过上限时，启动请求立刻得到明确的 `SYSTEM_BUSY`，而不是无限拉起新的执行和 CLI 子进程；每工作流上限仍然独立生效，现有 `WORKFLOW_BUSY` 契约不变。

**Blocked by:** 03 工作区解析与租约拒绝.

**Status:** ready-for-agent

- [x] 新增全局并发设置：0 = 不限；新库默认 4，已有库升级保持 0，避免改变既有行为
- [x] 启动时同时检查全局上限与每工作流上限；全局超限返回 409 `SYSTEM_BUSY`，每工作流超限仍返回 `WORKFLOW_BUSY`
- [x] 准入通过后才获取工作区租约；准入失败不创建执行记录、不产生副作用
- [x] 运行中/拒绝次数可观测，并通过运行时统计或设置页展示
- [x] 设置页可查看/修改上限；值为 0 时显示“不限”的风险提示
- [x] 并发启动测试断言两个上限同时生效；`-race` 通过
- [x] 关闭排队时，既有启动行为与错误语义逐位不变
