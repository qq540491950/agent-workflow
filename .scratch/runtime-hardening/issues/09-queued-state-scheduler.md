# 09: QUEUED 状态与调度器

**What to build:** 用户开启排队后，超过并发上限的启动不再被拒绝，而是进入 `QUEUED` 并返回 202。调度器在槽位释放时按公平策略取出排队执行；排队中的执行不占用工作区、不启动任何子进程，也可以被取消。

**Blocked by:** 04 工作区租约生命周期, 08 全局并发上限与 SYSTEM_BUSY.

**Status:** ready-for-agent

- [x] 新增 `QUEUED` 执行状态与 `queued_at`；状态迁移走 CAS，合法迁移为 `QUEUED → RUNNING / CANCELLED / FAILED`
- [x] 新增排队开关、队列长度上限与调度策略设置；关闭排队时保持既有 409，开启时超限返回 202 + `QUEUED`
- [x] 调度器在全局/每工作流槽位释放时取出排队执行，获取工作区租约后启动
- [x] 排队中的执行不获取工作区、不启动 CLI、不产生节点事件
- [x] 取消 `QUEUED` 走 CAS 落 `CANCELLED`，从队列移除并发出取消事件
- [x] API 对 `QUEUED` 返回队列位置；位置按 `queued_at` 稳定排序
- [x] 后端集成测试覆盖开启/关闭排队、上限释放、取消排队与无副作用；`-race` 通过
- [x] 状态徽标/过滤所需的前端类型同步（界面本身见 11）
