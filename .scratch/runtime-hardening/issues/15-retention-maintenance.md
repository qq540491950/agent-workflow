# 15: 保留策略与维护端点

**What to build:** 运维人员可以选择保留多久的事件与执行记录，先 dry-run 看清将删除多少数据，再正式清理；默认不自动删除，避免升级时误删审计。清理只针对已经落定的执行，不影响运行中、等待人工或排队中的执行。

**Blocked by:** 13 事件游标与监控增量.

**Status:** ready-for-agent

- [x] 新增事件保留天数、执行保留天数、单执行最大事件数设置；默认 0 = 不自动删除
- [x] 新增维护端点，支持 `dry_run` 返回将删除的事件/节点/制品/执行数量与估算字节数
- [x] 正式清理按 events → artifacts → execution_nodes → executions 顺序执行，只处理终态执行
- [x] 不清理 `RUNNING` / `WAITING_USER` / `QUEUED`；不破坏外键/引用一致性
- [x] 设置页提供保留策略与手动清理入口，明确提示删除不可恢复；清理结果可读
- [x] 清理幂等；失败时有明确错误；备份/导出语义不受影响
- [x] 测试覆盖 dry-run、只删终态、保留期 0、重复清理与清理后列表/详情可读
