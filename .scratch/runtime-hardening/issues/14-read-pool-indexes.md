# 14: 只读连接池与索引（wide refactor）

**What to build:** 把读请求从唯一的 SQLite 写连接上分流出去：保留一个写连接处理状态迁移、事件落库和元信息写入，增加只读连接池处理列表、详情、事件与统计查询；同时补上执行/事件表缺失的复合索引和幂等迁移。用户感受到的是长执行不再被 UI 查询拖慢，历史数据量上来后查询仍走索引。

**Blocked by:** 12 执行列表摘要与游标分页, 13 事件游标与监控增量.

**Status:** ready-for-agent

- [x] 写连接保持单连接；新增只读连接池，所有读查询不得在读池上执行写语句
- [x] 执行表补 `(state, created_at)` 与 `(workflow_id, created_at)` 复合索引；事件表补 `(execution_id, seq)` 复合索引
- [x] 旧库启动时幂等补列/补索引；不删除旧列、不重写业务数据；迁移失败显式报错
- [x] 列表、详情、事件、统计读路径按调用点分批迁移到读池，每批保持绿；完成后删除旧读路径（expand–contract）
- [x] 不再出现“持有未关闭 rows 又发起查询”的单连接死锁形态；嵌套查询有回归测试
- [x] 查询计划验证复合索引被使用；基准显示读请求不再与同步事件写入长期互相阻塞
- [x] 既有行为与脱敏测试全绿；`-race` 通过
